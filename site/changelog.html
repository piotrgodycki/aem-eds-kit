v0.4.93 2026-11-14

Added

  • A draft can start on the branch you name, e.g. after a ticket: eds block from-design … --draft --branch feature/CURLY-111, or eds draft refine <name> "…" --branch bug/CURLY-123 when it starts the draft. Every version is committed and pushed there (its preview is feature-curly-111--<repo>--<owner>.aem.page), and accept on the branch, update and reopen use it. The branch is kept in the draft and never renamed; the name is checked (git's rules, never main or master). Without it, drafts stay on draft/<name> (EDS-209)

v0.4.92 2026-11-14

Changed

  • Commits the kit writes are in English and no longer quote the reviewers' notes, whatever language those were in: a draft version on draft/<name> is hero v3: changes from review (first version, or the block as it was for v1), and draft accept --commit says Accepted draft v3 after 3 versions. The notes stay in the draft and its review; the pull request text is the agent's English summary. The agent is also told to write everything it adds to the files in English (code, comments, class names, Universal Editor labels, placeholder copy) whatever language the request is in; only copy from the design, or text a request quotes exactly, stays as it is (EDS-207)

Changed

  • The kit is developed with pnpm: pnpm-lock.yaml replaces package-lock.json (same versions), packageManager pins pnpm, and CI and the Publish workflow install and run the checks with pnpm. The package is still published with npm publish --provenance to npm and GitHub Packages, and installs as before (EDS-205)

v0.4.90 2026-11-13

Fixed

  • A generated or changed block now passes the project's own lint. After the agent writes it, the kit runs the project's stylelint and eslint (from node_modules/.bin, with the project's config; no npm or pnpm involved) with --fix, then again: what is left is a failed check, so the draft version shows issues instead of the pull request failing CI (e.g. stylelint's alpha-value-notation on rgba(…, 0.35)). Projects without them are skipped (EDS-203)

v0.4.89 2026-11-13

Fixed

  • Draft versions of a block that is already in the project (in blocks/ on the default branch and on disk) can be committed on draft/<name> again: eds draft push, refine --push and accept --on-branch stopped with "(use -f to force removal)" from git. The working tree is still left alone (EDS-201)

v0.4.88 2026-11-13

Added

  • An accepted draft can be reopened, and a draft's branch brought up to date. eds draft reopen <name> takes an accepted draft back into review with its versions and branch (its open pull request simply gets the next pushes). eds draft update <name> fetches origin and merges the default branch's newer commits into draft/<name> with a merge commit written by git's plumbing (the working tree is untouched), then pushes it; on a conflict the branch stays as it was and the conflicting files are named. eds draft list says how many commits each branch draft is behind (behind, as of the last fetch) (EDS-197)

v0.4.86 2026-11-13

Added

  • eds draft describe <name> [version]: the agent writes the pull request for a draft version in English: a Conventional Commit title and a description with Summary, Changes in review (one line per distinct change, never quoting the reviewers' notes, whatever their language) and How to check; --json emits a description event (EDS-195)
  • eds draft shot <name> [version] screenshots a draft version (the accepted one, else the latest) at each of its breakpoints with headless Chromium, into its __snapshots__/ folder: the baselines eds block test compares against once the block is accepted. --push commits them on draft/<name>, so a pull request can show them; --json emits a shots event. Screenshots (here and in eds block test) use the browser EDS_CHROMIUM names, else Playwright's own Chromium, else the Chrome or Edge already installed, so no separate browser download is needed (EDS-193)

v0.4.85 2026-11-13

Added

  • A yes in words. eds ask --input can carry pending, the action proposed under the last answer; the agent is told it waits for the developer's yes, and when the latest message just accepts it ("yes", "ok", "do it", any language) the answer event says accepts: true, so the caller runs that very action. An accept with no pending action, or one the agent invents, is never reported; a "yes, but…" gets a changed proposal instead (EDS-188)

v0.4.84 2026-11-13

Added

  • A draft can live on a git branch, so it has a live preview on aem.page that anyone can open. --push on eds block from-design --draft and eds draft refine, or eds draft push <name> [version], commits the version on draft/<name> (the first one off the default branch, the review comment as the message) and pushes it to a GitHub origin; the commits are written with git's plumbing, so the working tree, the current branch and staged changes are never touched. draft.json keeps the branch, each version's commit and the preview (https://draft-<name>--<repo>--<owner>.aem.page/), and --json emits a pushed event. eds draft accept <name> [version] --on-branch makes that version the branch's tip (pushing it; an earlier version goes on top as a new commit) and leaves blocks/ alone; its accepted event carries the branch and a pull request's title and body for the caller to open (EDS-190)

v0.4.83 2026-11-13

Added

  • Change a block already in blocks/ without a design. eds draft refine <name> "<change>" with no draft for it starts one from the block as it is (v1, keeping the design it came from, if any) and makes the change as v2; nothing reaches blocks/ until it's accepted, and the commit reads "update <name>". eds ask may now propose a change to any block in blocks/ as well as to open drafts, so the studio's chat changes hero straight away instead of asking for a design (EDS-184)

v0.4.82 2026-11-13

Fixed

  • eds ask proposes a change only to an open draft. It tells the agent which drafts are open, that a block in blocks/ is not one, and that a new block needs a design link (without one, the agent asks for it). A proposed refine naming any other draft is dropped, so the studio no longer offers to change a draft that doesn't exist (EDS-182)

v0.4.81 2026-11-12

Added

  • eds ask: ask your agent about the project in one read-only turn, kept inside the project like generation (Claude Code read tools only, Codex --sandbox read-only in the OS sandbox, local models get text). It keeps no conversation: --input takes the message, earlier turns and attachments as JSON, and --json returns an answer event. The agent may propose building a block or refining a draft; eds returns the proposal and never runs it (EDS-167)

v0.4.80 2026-11-12
