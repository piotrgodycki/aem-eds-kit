aem-eds-kit / End-to-end test

Test run · 19 Oct 2026 · v0.4.35

A full screen, design to EDS blocks

We ran the whole example page (the HTML twin of the Figma example file, 11 blocks) through eds block from-design with a real AI agent, rendered every block in the preview harness and screenshotted it next to the design. Nothing below was retouched.

●22 / 22 blocks generated ●18 / 18 clean in eds block check ●10 / 11 within 2 px height at 1440 (scrape) ●$0.48 scrape · $0.24 PNG, whole screen

How it was run

Two design sources, the same 11 blocks each. The agent was Claude Code on its default fast model (Haiku), one run per block, no hand edits.

⌁Stitch / Framer path: scrape

The live page is opened in headless Chromium and its computed layout, type and colours are embedded in the prompt.

$ eds block from-design <page-url> \
    --provider stitch --name hero

◇Figma path: frame exported to PNG

The no-token route: each block frame as an image. The example file is 1:1 with the page, so each section at 1440 px stands in for its Figma frame.

$ eds block from-design ./hero.png \
    --name hero
  1. Generateeds block from-design for each of the 11 blocks; the agent writes JS, CSS, the Universal Editor model and a preview mock.
  2. Rendereds block test --update --widths 390,768,1440 screenshots every block in the preview harness.
  3. Checkeds block check runs the content and accessibility checks on every content block.
  4. CompareEach block is screenshotted in the harness and pixel-diffed (pixelmatch) against the same section of the design.
!

Placeholders are on purpose. The prompt forbids shipping copied text or design-tool image URLs: content comes from authoring. Generated blocks therefore render placeholder copy and grey image boxes, and most of the pixel difference is that. Judge layout, spacing and type, not words.

What the run found and fixed

Running a whole screen, not one block, surfaced three bugs in the CLI. All three are fixed in v0.4.35 with tests:

  • The agent never started on a full-page scrape. The 146 KB prompt was passed to claude as one argument, past Linux's 128 KB limit (E2BIG). The prompt now goes in on stdin and the scraped spec is embedded as compact JSON (130 KB → 54 KB).
  • eds block test --design always crashed in the design↔render diff. Fixed, with a unit test.
  • Scraped frame widths were recorded as default widths, so the preview didn't mark them as real design frames. They now keep source: "scrape".

Still open: eds block check passed the PNG-path hero and footer, so it doesn't yet catch a preview mock nested deeper than decorate() reads. The Figma REST and MCP paths need a token or a Figma MCP connection and weren't part of this run.
