AEM EDS Studio for the team

AEM EDS Studio lets people who aren't developers build Edge Delivery blocks: describe what you want, link a design, review the block on desktop, tablet and mobile, and send it on. Experienced developers review the result and merge it. This guide sets the studio up for someone who has never opened a terminal, and the repository so that only developers can merge.

●One pasted line, once ●Sign-in inside the app ●Developers merge

Who does what

WhoDoes
The team (product, marketing, design, content)Links a design or describes a change, reviews the draft on three screen sizes, asks for changes in plain words, and sends it to a developer.
DevelopersReview the pull request the studio opens, ask for changes or approve, and merge. Nothing reaches the site's code before that.
The agent (Claude Code, on your own account)Writes the block. It works only inside the chosen project, never on the rest of your computer.

1. Install the studio

Download it from the Studio section: .dmg for macOS (Apple Silicon or Intel), .exe for Windows. It brings everything it runs, so there's no Node or other developer tool to install for it.

The builds aren't signed by Apple or Microsoft yet, so the first launch asks once: on macOS, open System Settings → Privacy & Security and choose Open Anyway; on Windows, choose More info → Run anyway.

2. Install the agent: the one terminal step

The studio uses Claude Code with your own Claude account. Installing it is the only step that needs a terminal, and it is one line you paste once. Claude Code's own installer doesn't need Node.

macOS: press ⌘ + Space, type Terminal, press Enter, paste this line and press Enter:

$ curl -fsSL https://claude.ai/install.sh | bash

Windows: open the Start menu, type PowerShell, open it, paste this line and press Enter:

> irm https://claude.ai/install.ps1 | iex

You need a Claude plan that includes Claude Code. If a terminal isn't for you, ask a developer or your IT to do this step; it takes a couple of minutes and is never needed again.

✦

The studio's Settings → Setup tab checks this for you: it shows a green tick when the agent is installed, and says what is missing otherwise.

Using Codex, or installing through npm? Install Node.js first

Claude Code's installer above doesn't need Node.js, and neither does the studio. You need Node.js only for Codex (OpenAI's agent, with a ChatGPT plan) or to install an agent with npm:

  1. Open nodejs.org and download the version marked LTS.
  2. Open the downloaded file (.pkg on macOS, .msi on Windows) and click through the installer with the default choices.
  3. Open a new Terminal or PowerShell window (one opened before the install doesn't see Node yet) and check it: node -v prints a version such as v22.x.
  4. Install the agent: 
    $ npm install -g @openai/codex          # Codex
$ npm install -g @anthropic-ai/claude-code   # or Claude Code through npm
    On macOS, if it says permission denied, don't use sudo: install Node.js again from nodejs.org, or ask a developer to set npm up for your user.

Codex is kept inside the project on macOS and Linux. On Windows it can't be, so the studio doesn't offer it there.

3. Sign in, inside the studio

Open Settings (the gear in the bottom-left corner) → Setup. Next to AI agent, choose Sign in: your browser opens Claude's own sign-in page, and the studio picks the login up when you're done. No terminal, and the studio never sees your password.

4. Connect GitHub

In Settings, choose Connect GitHub. The studio shows a short code; enter it on github.com and allow access. Then choose Choose repositories on GitHub and pick only the repositories you work on: the studio can't see any other.

For a repository that belongs to your company's GitHub organization, an organization owner may have to approve the app once.

5. Your first block

  1. Add project → pick the repository.
  2. Paste a design link (Figma, a web page) and give the block a name, e.g. hero.
  3. Review the draft on desktop, tablet and mobile. Ask for changes in plain words; each round is a new version.
  4. Accept the version you like: the studio puts it on its own branch and opens a pull request for a developer.

Nothing changes on the site until a developer approves and merges that pull request.

For the team lead: only developers merge

The studio has no merge button, but a GitHub permission is what really decides who can merge. Set up the repository once:

  • Branch protection on main (Settings → Branches, or Rules): require a pull request with at least one approving review before merging.
  • A CODEOWNERS file naming the developers, with Require review from Code Owners turned on, so the approval has to come from one of them.
  • Write access for the team, so they can push the studio's branches and open pull requests. With the protection above, write access doesn't let them merge into main.
  • The GitHub App approved for the organization, if your organization restricts apps.

FAQ

Do I need to know how to code?

No. You describe the block and link a design; the agent writes the code and a developer checks it before it reaches the site.

Can the agent see the rest of my computer?

No. The studio runs only agents it can keep inside the chosen project: Claude Code in its restricted mode, Codex in an operating-system sandbox, or a local model. Cursor can't be kept in and isn't offered.

Who pays for the agent?

The agent runs on the Claude plan you sign in with. The studio's Usage window (bottom-left corner) shows how much of your plan's 5-hour and weekly limits the studio's work has used.

Can I break the site?

No. Drafts live outside the site's code; accepting one opens a pull request, and only a developer can merge it.
